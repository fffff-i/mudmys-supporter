# 幕間ノート

マーダーミステリーのシナリオ資料をまとめ、現在の状況、根拠付きの出来事、優先して確認する行動を整理するWindowsデスクトップアプリです。シナリオごとに資料と方針履歴を分けて保存します。

## 主な機能

- シナリオ概要、テキスト、PDF、画像を保存。文章・複数ファイル・貼り付け画像を同じ窓口に並べ、「資料に追加」またはCtrl+Enterでまとめて確定します。入力・選択・貼り付けだけでは登録や解析を行いません。
- 資料名は本文の先頭行やファイル名から補完します。公開範囲の初期値は「不明」で、資料名と公開範囲の指定は任意です。HOの役・目的の再入力は不要です。
- 資料の見出し・解析本文を編集し、解析対象から外す・戻す操作ができます。初回本文・添付原本・解析や行動履歴の保存当時の出典は保持します。
- 現在の状況、時刻・人物・出来事の索引、事実・仮説・未確認事項を表示します。
- 次に誰へ何を確認するかを優先順に提案し、理由と資料の根拠を確認できます。
- 自分の役・目的・秘密を任意に登録し、解析へ含めるか選べます。
- 行動は「完了」「見送る」を1回押すだけで履歴へ残せます。理由・得た回答の履歴メモは任意で後から追加できます。
- 更新時は送信を許可した履歴のID・相手・目的・手順・未確認の前提・日時・任意メモを参照します。AIへの指示と内容照合で同じ行動の通常の再提案を抑え、前提が変わって再確認する場合は元の履歴と具体的な違いを表示します。
- 行動の根拠資料は任意です。「根拠資料の公開範囲」と「秘密への配慮」は別々に表示し、発言例・秘密への配慮は詳細を開かず読めます。
- シナリオごとのデータをローカルに保存し、バックアップを書き出せます。
- アプリ起動中の文章・選択ファイル・貼り付け画像・資料の編集・公開範囲・概要・役プロフィールの下書きはシナリオごとに保持し、切替時に自動復元します。画像の読込中や保存中の追加入力も保持します。

## 開発環境

Node.js 22.13以降とnpmが必要です（Viteは20.19以降または22.12以降、PDF.jsが22.13以降を要求します）。

```powershell
npm install
npm run dev
```

確認には次を実行します。

```powershell
npm test
npm run build
```

シナリオ切替と保存中の下書きを画面から検証するには、ビルド後に `node scripts/verifyScenarioDrafts.cjs` を実行します。Edge / Chrome / Chromiumをヘッドレスで使い、架空シナリオ、ブラウザーの一時profile、結果をこのコピーの `.local/scenario-drafts-ui/` に保存します。Electronや実際のAI送信は使いません。ブラウザーが標準位置にない場合は環境変数 `MAKUA_HEADLESS_BROWSER` に実行ファイルのパスを指定できます。

PDF原本表示と出典を画面から検証するには、ビルド後に `node scripts/verifyPdfSources.cjs` を実行します。同じヘッドレス方式で文字・画像・混在ページ、旧データ、読み取り失敗、表示上限、遅延応答、保存当時の出典を検証し、架空データと結果を `.local/pdf-sources-ui/` に保存します。

行動の1クリック保存、任意メモ、保存中のシナリオ切替と追加入力は、ビルド後に `node scripts/verifyActionHistory.cjs` でヘッドレス検証できます。架空データと固有のブラウザープロファイルだけを使い、結果はこのコピーの `.local/action-history-ui/results.json` に保存します。

資料の一括追加、Ctrl+Enter・IME、画像読込や保存中のシナリオ切替、失敗後の再追加、本文編集、除外・復帰は、ビルド後に `node scripts/verifyEvidenceIntake.cjs` で検証できます。実クリップボードやOSダイアログは使わず、候補と入力イベントをモック化し、結果は `.local/evidence-intake-ui/results.json` に保存します。

Windows向けportable版を生成するには `npm run package:portable` を実行します。生成物は `release-v0.3.0/` に出力されます。このフォルダーは公開リポジトリには含めません。

## AI接続

AIは初期状態では未接続です。未接続でも資料の保存、整理、シナリオごとのバックアップを利用できます。設定から次の接続先を選べます。

- **OpenAI API:** APIキーをWindowsの暗号化ストレージに保存し、同意した資料をAPIへ送信します。ChatGPT/Codexの契約とは別のAPI利用料がかかる場合があります。
- **Ollama:** このPCのlocalhost上のOllamaへ接続します。画像の読解可否は選んだモデルによって異なります。PDFページ画像は送信せず、抽出できたテキストを使います。
- **Codex（ChatGPTの契約枠）:** 公式Codex CLIのApp Serverを使う実験的な接続です。設定画面から専用profileへのChatGPTサインインを開始し、表示されたデバイスコードを利用者自身が公式認証ページで入力します。アプリはブラウザーを開かず、通常のCodex認証情報をコピーしません。Platform APIへフォールバックしません。

OpenAI APIとCodexでは、シナリオ概要、資料全文、画像、PDF、送信を許可した方針・仮説・行動履歴（完了・見送り・更新、任意メモ）を選択した接続先へ送信します。「自分の役・目的・秘密を解析に含める」がOFFの場合、役プロフィールと、役情報を使った解析に由来する過去の文章を除外します。由来を確認できない旧データも除外します。AIが後から付けた退役理由と任意メモも由来を保持し、役情報を含む履歴は送信しません。履歴メモと以前のAI出力自体は事実の出典にはしません。この扱いはOllamaにも共通です。以前の整理結果と方針はローカルの履歴で閲覧できます。同じ役情報を含むHOを資料として追加した場合は、HOを含む資料の送信設定に従います。利用前に設定画面の送信範囲を確認してください。自動更新は個別の同意が必要です。

Codexでは利用可能モデルをCLIから取得し、選択したモデルに切り替えます。モデルが利用できない場合に別のモデルやAPIへ自動変更しません。対応CLIが必要で、App Server仕様は変更される可能性があります。shell、apps、remote plugins、multi-agent、web searchを設定で無効にし、read-only sandboxとネットワーク制限を指定します。予期しないツールや権限要求では解析を中断します。ただし、App Serverの読み取り範囲を個別指定できず、内部機能すべての無効化も保証できないため、完全に隔離された実行環境ではありません。

## 資料と保存

資料詳細の「見出し・本文を編集」では、解析に使う本文だけを更新します。編集本文の引用は「編集本文と一致・原本未照合」と区別します。過去の解析と行動履歴の出典は、その解析で使った見出し・本文で開き、資料一覧からは現在の原本と編集本文を開きます。変更を反映する前の整理結果には、その旨を表示します。保存当時の編集内容が記録されていない旧履歴では、初回原文を表示して説明します。

「解析対象から外す」は同じ資料IDと原本を保持します。対象外の資料の本文・添付・見出し、およびその資料に由来する過去の仮説・行動・履歴は全接続先への入力から除外します。資料を1件でも除外した場合、資料の由来を確認できない旧結果も保守的に除外します。任意の履歴メモは、元の行動・以前のメモ・メモ保存時の解析対象資料の由来を保持します。「解析対象に戻す」で再利用できます。

原文と添付ファイルは要約で置き換えずローカルに保持します。PDFは全ページの本文・抽出状態・ページ数を記録し、本文引用を該当ページの原文と照合します。同じページの本文と画像も区別し、抽出に含まれない画像引用は、送信した実在する原本・ページを確認して「画像読取・引用未照合」と表示します。Ollamaへ送っていないPDF画像は引用できません。出典を押すと同じ画面で該当PDFページ・画像・テキストを開けます。旧データは保存済み原本からページ情報を補完し、原本が欠落しても保存された本文・解析は閲覧できます。AIの要約・引用・人物解釈は誤る可能性があるため、判断時は原資料を確認してください。

1ファイル20 MiB超は取り込み前に拒否し、保存しません。取り込み済み資料の解析対象が合計40 MiBまたは抽出テキスト30万文字を超える場合、解析を止めて原本を保持します。CodexではさらにPDF合計200ページと生成画像合計40 MiBを、このアプリ側の安全上限として設定しています。いずれもCodexの公式上限を示す値ではありません。超過時にページや文章を黙って切り捨てません。

容量表示は保存済み原本と解析対象の添付を分け、テキストメモやテキストファイルの本文を添付送信量に加算しません。超過時は同じシナリオの資料一覧で本文を編集するか資料を解析対象から外して再開できます。取り込み候補に問題があれば候補だけ外して再確定できます。一括確定に失敗した場合も、既存資料と未確定の下書きは残ります。

シナリオはアプリのユーザーデータ領域へローカル保存されます。シナリオバックアップにはAPIキーやCodex専用profileを含めません。
